# 播放入口、标题与目录修订

2026-10-13用户报告WebDAV外部转圈后进入还要加载，以及未识别文件排在官方剧集前面；随后明确图一是顶部控制栏与顶部之间有空白，并要求标题包含当前集数。

根因：open_internal_player只对规则先开加载壳，普通WebDAV同步完成stream_only探测 / 字幕准备才打开Activity，React又用全局run等待，形成两个可见等待阶段；加载壳与后续open_player重复同步保存进度。现统一先验证本地索引、打开原生壳、同步上个播放器刚保存的样本，再异步准备媒体，保留同一operation / session的取消与晚到保护。播放入口独立pending去重 / 错误反馈，不显示全局浮层。

Range探测保持0-0 / 有效206 / 完整Content-Range校验，读取严格1字节并拒绝空 / 多余数据，让HTTP/1.1可复用该连接。没有移除来源验证、完整下载视频或改变解码配置；真实远端响应、字幕准备及解码仍可能耗时，不把进入页面快等同于首帧必然快。

原生顶部不再把displayCutout.top作为整个控制层的额外padding，保留横向安全距离与原有16:9画面。标题复用实际文件 / 规则当前标签，例如作品 · 第01集，人工映射优先。

原播放器按文件COALESCE集号排序，SQLite空集号靠前，OP等未关联文件因此排头。现在另建仅用于显示的episodeRows，复用本地缓存官方目录与TMDB图像映射；每集保留一个实际播放目标，当前文件优先，其次当前来源可用文件，其他可用版本保留在同集文件选择器。缺文件官方卡片不可播放，未匹配文件在独立底部分区。原rows仍是受限播放目标与文件候选，不创建假文件或改写用户关联。

验收脚本scripts/verify-player-entry.mjs检查真实React入口无全局浮层 / 去重 / 错误 / 窗口宽度；PlayerHeaderTest检查原生控制栏与视频顶部一致及官方集号。播放器实机脚本扣住初始WebDAV探测响应，验证命令先返回且PlayerActivity已在前台，再放行媒体；同时核对官方目录 / 未匹配分区、标题、续播、取消与失败。最终结果和APK见AI_HANDOFF.md。
