# 安卓目录整理与分集播放来源

2026-10-10，基线 `365a7e3`，本轮为 v0.6.0 本机验收（versionCode 6000），不创建公开 Release 或覆盖公开 v0.5.2 资产。新增迁移 0030，递增安装版本可阻止旧包直接覆盖新版数据库。

## 行为

- 待整理按已索引的真实目录浏览，入口为来源 → 分类 / 年份目录 → 作品文件夹 → 季度 / 特别篇。目录浏览不重新下载或枚举网盘正文。
- 新增 WebDAV 后自动执行首次扫描与可靠动漫识别。之后新增文件需手动点击“更新并识别”；应用启动不静默重扫。仅扫描目录属性，不下载视频。
- “连续识别动漫 / 自动识别此目录”将选定目录提交给 Rust 后台队列，可靠、无歧义时归档，失败或不确定时保留待整理。页面可退出，后台通知服务保护扫描与识别，显示实际处理数 / 当前文件夹。每个来源同一时刻一个整理任务，全局最多两项执行；自动确认在事务中再次核对文件仍未关联且来源启用。明确电影 / 真人电视剧目录不送入动漫匹配器，仍通过单项类型选择核对。
- 基本作品与文件归属先落库，补充资料 / 封面延后执行，不逐项刷新完整媒体库。队列 / 游标 / 待补图存于独立命名的现有设置记录；完成后移除无用途队列，未完成任务保留以供明确继续，不新建媒体库或修改历史迁移。
- 后台整理可以停止；扫描取消仍遵循原子索引提交规则，识别等待当前项结束。系统强制结束应用后显示中断，用户可明确继续；不承诺被强制停止后仍运行。采用 Android dataSync 前台服务、有限时唤醒锁，无开机启动 / 电池优化豁免 / 新依赖；遵守系统后台时限。
- “逐个整理”提供文件勾选、类型 / 季度、候选预览、确认与跳过；确认后停留在整理流程继续下一项。代表文件只选当前勾选且可用的视频；电影初选单文件，电视剧按季度调整初选。确认提交候选绑定的代表文件 ID，避免使用过期候选。
- 人工整理显示当前真实目录；待整理返回时恢复目录位置。单项搜索采用本地等待状态，关闭后旧响应不覆盖其他文件的候选；保存关联仍短暂保护原子操作。
- 作品详情的“剧集”以官方分集为主，同一集可选择本地、WebDAV 或具体文件版本。默认优先上次观看的可用文件；未关联分集的文件单独列出，不用文件顺序虚构集号。未来来源可沿用作品 / 分集 / 文件身份，本轮不实现规则源或网盘账号直连。
- 来源页“移除连接”只移除应用连接，保留网盘文件、作品、评分、笔记、观看位置、文件身份与已有缓存。文件变为不可用，其他来源仍可播放；活动扫描期间拒绝移除。新增迁移 0030 记录连接移除时间，保留关联所需内部索引，凭据通过既有凭据桥删除；不会向 WebDAV 发送 DELETE。
- 活动后台整理期间也拒绝移除 / 改动来源和重复扫描，避免队列与索引范围冲突。

## TMDB 设置与分集剧照

- Read Access Token 前后空白及可选 Bearer 前缀在保存前规范化，最长 8192 字节，不接受内嵌空白 / 控制字符；安全存储沿用 Android Keystore 的加密与读回校验，前端只获得配置状态。
- 保存完成独立提示；后续状态读取失败不会误报保存失败。“测试已保存的连接”用保存凭据请求 TMDB configuration，绕过资料缓存，错误中不返回密钥。
- 安卓剧集先读现有剧照绑定与缓存，再后台核对 TMDB 季度 / 分集；可见图片按既有并发限制缓存，失败可手动更新，缺图回退中性播放占位。不以海报冒充分集画面，不改官方分集、文件映射或观看记录。
- 复用既有 TMDB 标题 / 日期 / 集号偏移核实规则；无唯一对应时保留警告，不保证所有作品都有剧照。独立验收用假的长 Token 检验存储；随后在用户原调试包直接使用现有安全配置测试连接成功，未读出或复制 Token。一部已入库动画取得 12 张真实剧照，本地缓存与 12 张图片实际解码显示均已验证。
- 实现依据：[Android dataSync 服务](https://developer.android.com/develop/background-work/services/fgs/service-types)、[服务超时处理](https://developer.android.com/develop/background-work/services/fgs/timeout)、[TMDB 应用认证](https://developer.themoviedb.org/docs/authentication-application)。

## 批量匹配剧集与续季编号

- 详情“剧集”页及“概览 → 资料管理”增加批量匹配入口，目标固定为当前作品。默认只列可用的未关联视频，可显式显示已关联文件重新核对；已有人工关联不默认勾选。
- “按文件集号对应”分别设置文件起始集号、官方起始集号：例如文件 13、官方 1，预览 13 → 1、14 → 2、…、24 → 12。两数之差只用于明确确认的正片映射，不按固定 12 集猜测，不从剩余文件的最小编号推断续季边界。特别篇类型单独显示并保守核对。无明确文件编号时可切换自然排序连续匹配，多个压制版本需要逐行核对。
- 复用已有纠错诊断 / 预览令牌 / 原子确认 / 人工覆盖记录。保存官方对应后，原始文件名、解析集号、媒体 ID、作品身份、观看位置与未选文件保留；刷新资料 / 重建关联后仍优先使用人工映射。不新增迁移，也不改旧迁移。
- 官方分集未缓存时可刷新；不唯一 / 季度冲突 / 编号范围异常的项目不可在此批量确认。改动编号 / 文件范围使旧预览失效，后端再次核对输入、官方分集与实际 SAF 目录上下文，拒绝过期保存。
- 按用户明确选择移除漫画 / 小说 / 视频详情的“个人记录”按钮，删除因此失去入口的安卓编辑面板；已有数据及追番状态 / 收藏入口保留。

## 根因与范围

- 旧 WebDAV 分组固定以根目录下第一层作为作品目录，接入整个服务后会把“动漫 / 年份”等分类目录下不同作品合并。确认范围又直接用编码路径判断季度，和展示分组可能不一致。
- 虚拟来源改用最近的实际作品目录，越过季度、BD / 字幕等容器；SAF 使用 `android_documents.relative_path`，保留原始不透明文档 ID 供播放与授权。分组、确认和分集重建共用实际目录上下文。
- WebDAV / SAF 确认范围保留目录大小写；Windows 本地目录原有口径保留。混有不同命名作品的文件夹不因一个高分候选自动归档整组。
- 本轮不猜测回滚此前已经错归档的作品。已有错误关联从作品详情的重新匹配 / 分集纠错预览中核对。缺少作品名的文件仍需手动搜索。
